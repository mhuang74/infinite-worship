# Upload pipeline: presigned R2 PUT, BFF finalize enqueues SQS, single public bucket

Uploads bypass all servers: the BFF (`POST /api/uploads`) mints a presigned R2 PUT URL and inserts a `pending` Song row in Neon; the browser PUTs audio directly to its final key in a single public-read R2 bucket; the browser then calls `POST /api/songs/{id}/finalize`, which sends the SQS message that triggers the analysis Lambda. The explicit finalize call exists because R2 event notifications cannot reach SQS/EventBridge — only Cloudflare Queues — so the S3-style automatic trigger is unavailable and a Cloudflare Queue bridge was rejected as a second vendor's moving parts. Playability is gated by Song status in Postgres, not by bucket layout: un-analyzed audio sits at its public key but is undiscoverable (no listing, unguessable content-addressed key) and unplayable (no Analysis JSON until the Worker writes one). The Worker validates object size/content-type before downloading — presigned PUTs cannot enforce size limits (R2 doesn't support POST policies) — and marks violators `failed`; an R2 lifecycle rule expires objects that never finalize. Songs over 10 minutes are `failed` by the Worker to keep the 15-minute Lambda ceiling unreachable. Infrastructure is Terraform (AWS + Cloudflare providers); the Neon project is a one-time manual snowflake. There is no separate cloud dev environment: development happens against the prod resources.

## Consequences

- A crashed browser tab leaves a pending Song + orphaned audio until the lifecycle rule collects it.
- Anyone with a presigned URL can overwrite that key until the lifecycle/rule boundary; content-addressed Song IDs make collisions benign (same content, same key).
- No dev/prod isolation means test uploads appear in the production library; accepted in exchange for zero dev-environment maintenance.
- The public bucket is served from a **custom domain on a Cloudflare-managed zone**, not the managed `r2.dev` subdomain: r2.dev is rate-limited, non-production-only, and supports no caching — which would defeat the CDN-cached zero-egress playback that justified R2. The custom domain enables Cloudflare cache ("Cache Everything") in front of R2.
- The bucket needs an explicit **CORS rule allowing the Vercel origin(s)**: the Player fetches audio as a blob into the Web Audio API (not an `<audio>` tag), so cross-origin reads are blocked without it. This is part of bucket setup, not an afterthought.
