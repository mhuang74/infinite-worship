# Delivery: Vercel git integration for frontend, GitHub Actions for worker + infra

Frontend deploys via Vercel's git integration (push to main → deploy). The worker image and Terraform are delivered by GitHub Actions on merge to main: build the container image, push to ECR, update the Lambda function, `terraform apply`. Split rationale: Vercel's integration is free and idiomatic for Next.js, while the worker/infra pipeline has no equivalent zero-config path — and the "all manual" option was rejected because every deploy becoming a laptop ritual contradicts the ops-elimination goal. Observability is deliberately minimal: CloudWatch log groups, SQS redrive to a DLQ, one CloudWatch alarm on DLQ depth > 0, and failed Songs surfaced via status in the UI.

Worker images live in the private, Terraform-managed ECR repository `infinite-worship-worker` (`us-west-2`), not GHCR. The pre-serverless app (Flask backend + Nginx-fronted Next.js frontend, docker-compose on a Graviton `t4g.medium`) instead pushed two arm64 images from a laptop `application/build.sh` to the **public** ECR repo `public.ecr.aws/u4p9h6o7/mhuang74/infinite-worship` (tags `infinite-worship-{backend,frontend}-arm64-<YYYYMMDD>` and `-latest`), which `docker-compose.prod.yml` pulled without registry credentials. The Next.js-on-Vercel + container-image-Lambda migration replaced that path: the only app image is now the analysis worker in private ECR, built and pushed by GitHub Actions. Lambda's container-image path resolves `Code.ImageUri` from Amazon ECR, and same-account private ECR lets the function's execution role pull with the `EcrPull` grants already in `infra/worker.tf` — no second registry credential (GitHub PAT) in the pipeline. GHCR is not a native Lambda image source and would only add a mirror-into-ECR step. Terraform owns the private repo's lifecycle (`aws_ecr_repository.worker`, scan on push); CI pushes the mutable `:<git-sha>` tag after `amazon-ecr-login` in `.github/workflows/deploy.yml`. The 16 legacy public-ECR images remain only as an irreversible teardown item (`infra/README.md` cutover checklist); `public.ecr.aws/lambda/python:3.11` in `worker/Dockerfile` is the AWS base image, not app storage.
